# 토스증권 기반 주식 자동매매 시스템 PRD

## 1. 제품 개요

토스증권 Open API의 시세·계좌·주문 기능을 이용해 정해진 전략에 따라 주식을 자동으로 매매하는 개인용 시스템을 만든다.

초기 버전은 실제 주문을 보내지 않는 `DRY_RUN` 모드를 기본으로 제공한다. 사용자가 전략과 위험 설정을 충분히 검증한 뒤에만 실계좌 주문을 활성화할 수 있다.

> 이 시스템은 투자 판단을 대신하거나 수익을 보장하지 않는다. 모든 투자 결정과 손실 책임은 사용자에게 있다.

### 현재 구현 상태 (2026-09-24)

- PAPER 화면에서 가상 주문, 이동평균 전략과 위험 한도를 연습할 수 있다.
- LIVE 화면은 토스 실계좌의 총자산, 보유종목과 원화·외화 매수 가능 금액을 읽기 전용으로 보여 준다.
- 원화 예산 안에서 살 수 있는 국내 종목 후보와 부분 검색 결과를 당일 거래대금 인기순으로 제공한다.
- 검색 결과의 현재가, 오늘 등락률, 종목 유형과 순위를 표시하고 한 페이지에 8개씩 나눈다.
- 사용자가 하트로 선택한 관심종목은 PostgreSQL에 최대 20개까지 저장된다.
- LIVE 실제 주문은 아직 구현하지 않았으며 PIN을 설정해도 조회 화면의 주문 잠금은 유지된다.
- 토스 공식 Open API에 산업 분류 필드가 없어 산업·테마 표시는 보류한다.

## 2. 목표

- 토스증권 Open API로 국내주식 시세와 계좌 정보를 조회한다.
- 사용자가 설정한 단순한 규칙으로 매수·매도 신호를 만든다.
- 모의 주문을 통해 전략의 동작을 안전하게 검증한다.
- 실계좌 모드에서는 주문 전 위험 한도를 반드시 검사한다.
- 초기 위험 설정은 보수적, 기본(연습용 권장), 직접 설정의 세 가지 프리셋을 제공한다.
- 1회 주문, 종목별 투자, 전체 투자, 최소 현금, 일일 손실, 일일 주문 횟수, 수익 목표를 검사한다.
- 한도 도달 시 신규 매수를 중지하되 위험을 줄이는 매도는 허용한다.
- 자동 전량매도는 토스 API 연결 후 기존 보유분과 자동매매 보유분을 구분할 수 있을 때 별도로 설계한다.
- 모든 신호, 주문, 체결, 오류를 기록해 나중에 확인할 수 있게 한다.

## 3. 제외 범위

- AI가 종목을 임의로 추천하거나 매매 전략을 스스로 변경하는 기능
- 초단타·고빈도 매매
- 선물, 옵션, 가상자산 등 주식 이외의 상품
- 여러 사용자의 계좌를 관리하는 서비스
- 수익률 보장 또는 투자 자문 기능

## 4. 대상 사용자

- 자동매매를 학습하고 싶은 개인 개발자
- 자신의 규칙 기반 전략을 반복 실행하고 싶은 토스증권 사용자
- 실제 투자 전에 모의 실행 결과를 확인하고 싶은 사용자

## 5. 기술 선택 분석

이 프로젝트는 **Python과 FastAPI를 기반으로 개발한다.**

### Python을 사용하는 이유

- 주식 데이터 처리와 전략 계산에 필요한 라이브러리가 풍부하다.
- 비동기 처리를 이용해 REST API 요청과 WebSocket 실시간 데이터를 함께 다루기 쉽다.
- 백테스트, 데이터 분석, 자동화 코드를 하나의 언어로 작성할 수 있다.
- 코드가 비교적 간결해 바이브코딩 방식으로 개발하고 검토하기 좋다.

### FastAPI를 사용하는 이유

- 계좌, 시세, 전략, 주문 기능을 REST API로 구성하기 좋다.
- Python의 `async/await`를 지원해 실시간 시세 처리와 잘 맞는다.
- 요청 데이터 검증과 API 문서를 자동으로 제공한다.
- 이후 웹 대시보드나 모바일 앱을 연결하기 쉽다.

### 역할 구분

- **Python:** 시세 수집, 전략 계산, 위험 관리, 주문 실행, 백테스트를 담당한다.
- **FastAPI:** 자동매매 상태 조회, 설정 변경, 시작·중지, 주문 내역 조회를 위한 API를 제공한다.
- **별도 워커:** FastAPI 요청 처리와 분리되어 장중 전략을 지속해서 실행한다.

## 6. 핵심 사용 흐름

1. 사용자가 토스증권 API 인증 정보를 환경변수로 등록한다.
2. 시스템이 인증 후 계좌와 보유 종목을 조회한다.
3. 사용자가 감시 종목, 전략, 투자 한도를 설정한다.
4. 시스템이 실시간 시세를 받아 매매 신호를 계산한다.
5. 위험 관리 규칙을 통과한 신호만 주문 후보가 된다.
6. `DRY_RUN`에서는 모의 주문으로 기록하고, 실거래 모드에서는 토스증권으로 주문을 전송한다.
7. 사용자는 실행 결과와 오류를 로그 및 대시보드에서 확인한다.

## 7. MVP 기능 요구사항

### 7.1 인증 및 계좌

- OAuth 2.0 Client Credentials 방식으로 액세스 토큰을 발급한다.
- API 키와 비밀키는 코드나 Git 저장소에 저장하지 않는다.
- 계좌 목록, 보유 종목, 매수 가능 금액을 조회한다.
- 총자산은 국내 보유주식 평가금액과 원화 매수 가능 금액을 합산해 표시한다.
- 원화·외화 매수 가능 금액은 통화를 구분해 표시한다.

### 7.2 국내 종목 탐색과 관심종목

- 종목명 일부 또는 6자리 종목코드로 국내 종목을 검색한다.
- 검색 결과는 당일 거래대금 순위를 우선하며 한 페이지에 8개씩 표시한다.
- 종목 유형은 보통주, 우선주, ETF, 리츠, ETN 등 사용자용 한글 명칭으로 표시한다.
- 현재가와 오늘 등락률을 함께 표시한다.
- 현재 원화 매수 가능 금액 이하의 인기 종목을 후보로 제시하되 투자 자문이나 수익 보장으로 표현하지 않는다.
- 관심종목은 관리자 계정별로 PostgreSQL에 최대 20개까지 저장한다.
- 산업·테마 분류는 신뢰할 수 있는 외부 데이터 출처와 갱신 정책을 정한 뒤 추가한다.

### 7.3 시세 수집

- 국내주식 현재가와 1분봉·일봉 데이터를 조회한다.
- WebSocket으로 실시간 체결 데이터를 구독한다.
- 연결이 끊기면 제한된 횟수만큼 자동 재연결한다.
- API 호출 제한을 넘지 않도록 요청 속도를 제어한다.

### 7.4 전략

MVP에서는 이해하기 쉬운 이동평균 교차 전략 하나만 제공한다.

- 가상 시세는 2초 간격으로 갱신한다.
- 단기 이동평균은 최근 5개 가격, 장기 이동평균은 최근 20개 가격으로 계산한다.
- 단기 이동평균이 장기 이동평균을 상향 돌파하면 매수 신호를 만든다.
- 단기 이동평균이 장기 이동평균을 하향 돌파하면 매도 신호를 만든다.
- 단기·장기 이동평균 기간, 실행 간격과 주문 수량을 PAPER 화면에서 설정한다.
- 같은 신호로 주문이 중복 생성되지 않아야 한다.

### 7.5 주문

- 기본값은 실제 주문을 전송하지 않는 `DRY_RUN=true`이다.
- 지정가 매수·매도 주문을 지원한다.
- 주문 상태와 체결 결과를 조회하고 내부 기록과 동기화한다.
- 네트워크 오류가 발생해도 동일 주문을 중복 전송하지 않는다.
- 실거래 활성화 시 사용자에게 현재 모드가 명확하게 표시되어야 한다.

### 7.6 위험 관리

- 1회 최대 주문 금액
- 종목별 최대 보유 금액
- 하루 최대 주문 횟수
- 하루 최대 손실 금액
- 주문 가능 시간 제한
- 긴급 정지 기능(Kill Switch)
- 시세가 오래되었거나 API 상태가 비정상이면 신규 주문 차단

### 7.7 기록 및 조회

- 매매 신호와 발생 이유
- 주문 요청과 응답
- 체결 및 취소 내역
- 잔고 변화
- 오류와 재시도 기록
- 일별 손익 요약

## 8. 화면 구성

MVP는 간단한 웹 대시보드로 구성한다.

- **상태 화면:** 실행 모드, API 연결 상태, 장 운영 상태
- **LIVE 자산 화면:** 총자산, 매수 가능 금액, 보유 종목, 예산 내 종목 후보
- **종목 탐색:** 인기순 부분 검색, 현재가·오늘 등락률·유형, 페이지 이동
- **관심종목:** 검색 결과에서 추가·삭제하고 현재 상태를 카드로 조회
- **전략 화면:** 감시 종목과 전략 설정
- **주문 화면:** 주문·체결·취소 내역
- **로그 화면:** 신호, 위험 차단 사유, 오류 기록
- **제어 영역:** 자동매매 시작·중지 및 긴급 정지

## 9. 비기능 요구사항

- 비밀정보는 환경변수로 관리하고 로그에 출력하지 않는다.
- 로컬 관리자 계정 하나만 허용하며 계정 생성은 터미널 명령으로 분리한다.
- 관리자 비밀번호는 scrypt로 해시해 PostgreSQL에 저장한다.
- 로그인 5회 실패 시 계정을 일정 시간 잠근다.
- 인증 세션은 HttpOnly·SameSite 쿠키를 사용하고 기본 30분 후 만료한다.
- 주문과 자동매매 제어 요청은 CSRF 검사를 통과해야 한다.
- 로그인하지 않은 사용자는 대시보드, API 문서와 거래 API에 접근할 수 없다.
- 모든 금액과 수량 계산은 부동소수점 대신 정확한 숫자 형식을 사용한다.
- PAPER 거래는 서버 재시작 시 초기화하고, LIVE 주문은 재시작 후에도 복구·대조할 수 있게 영구 저장한다.
- 시간은 내부적으로 타임존 정보를 포함해 저장한다.
- 핵심 전략과 위험 관리 로직은 자동 테스트를 작성한다.
- 토스 API 반복 조회는 짧게 캐시하고 토큰 무효화 시 제한된 횟수만 재발급한다.
- 서버는 한 프로세스로 실행하며 빠른 반복 요청으로 외부 API 호출 제한을 넘기지 않는다.
- 운영 전 최소 1주일 이상 `DRY_RUN`으로 검증한다.

## 10. 권장 기술 구성

- **언어:** Python 3.12+
- **API 서버:** FastAPI
- **스케줄러/실행기:** asyncio 기반 워커
- **데이터베이스:** PostgreSQL
- **대시보드:** FastAPI가 제공하는 HTML/CSS/JavaScript 웹 화면
- **테스트:** Python unittest
- **배포:** 개인 PC 또는 단일 서버에서 Docker로 실행

## 11. 시스템 구성

```text
토스증권 REST/WebSocket
          ↓
     시세 수집기
          ↓
       전략 엔진
          ↓
     위험 관리 엔진
          ↓
 모의 주문 또는 실계좌 주문
          ↓
    DB 기록 및 대시보드
```

## 12. 개발 단계

### 1단계: 기반 구축

- 프로젝트 구조와 환경변수 설정
- 토스증권 인증, 계좌 및 시세 조회
- 웹 대시보드 구성
- PostgreSQL 관리자·세션·관심종목 저장
- 읽기 전용 LIVE 자산과 국내 종목 탐색

### 2단계: 모의 자동매매

- 이동평균 전략 구현
- 위험 관리 규칙 구현
- `DRY_RUN` 주문과 결과 기록
- 대시보드 구현
- PostgreSQL과 로그 구성

### 3단계: 검증

- 과거 데이터 백테스트
- 장중 모의 실행
- 장애 및 중복 주문 테스트

### 4단계: 실계좌 연동

- 사용자 확인 절차 추가
- 소액 지정가 주문부터 제한적으로 활성화
- 긴급 정지와 주문 복구 절차 검증

## 13. MVP 완료 조건

- 토스증권 인증과 시세·계좌 조회가 정상 동작한다.
- 최소 한 종목을 대상으로 전략 신호가 생성된다.
- `DRY_RUN` 주문이 중복 없이 기록된다.
- 모든 주문 후보가 위험 관리 검사를 거친다.
- 대시보드에서 상태, 보유 종목, 신호, 주문 기록을 확인할 수 있다.
- 주요 로직의 자동 테스트가 통과한다.
- 실제 주문은 명시적으로 활성화하지 않는 한 전송되지 않는다.

## 14. 미결정 사항

- 첫 지원 시장은 국내주식으로 제한한다.
- PAPER 감시 종목은 토스 국내 일일 거래대금 상위 10개로 구성하고 API 실패 시 대표 종목 10개를 사용한다.
- 토스증권 API 발급 전까지 가상 시세와 가상 주문만 사용한다.
- 초기 가상 투자금은 1,000만 원으로 설정한다.
- 종목별 최대 투자 금액
- 서버를 개인 PC에서 실행할지 클라우드에 배포할지
- 실거래 기능을 MVP에 포함할지 다음 버전으로 미룰지
- 산업·테마 분류에 사용할 신뢰 가능한 외부 데이터 출처와 갱신 주기
