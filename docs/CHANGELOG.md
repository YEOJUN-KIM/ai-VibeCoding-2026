# 작업 기록

## 2026-09-30

### 문서 구조와 개발 DB 백업 정리

- 문서를 현재 상태, 제품 요구사항, 가까운 로드맵, 보류 기능, PAPER 계산, 데이터 저장, 코드 구조와 변경 이력으로 분리했다.
- PRD와 로드맵에 중복되어 있던 PAPER 설명과 과거 완료 기록을 각각 단일 기준 문서와 변경 이력으로 모았다.
- 개발 단계에서는 스키마와 코드를 기준으로 재구성하고, 실사용 전 정기 백업·복구 시험을 도입하는 정책을 명시했다.
- Windows PostgreSQL 이전 때 만든 일회성 `auto_trader_20260930.dump`를 제거하고 재구성 기준인 `schema.sql`은 유지했다.
- 이전 완료 후 약 506MB의 `.paper-postgres` 데이터와 포트 55432 전용 시작·종료·이관 스크립트를 제거했다.
- 오래된 기본 전략을 현재 메타에 맞게 다시 만드는 `프리셋 갱신` 버튼을 후속 백로그에 추가했다.

### 장기투자 분석 1차

- 개발 중 예약 시각을 놓쳐도 실행할 수 있도록 `추천 새로 분석` 버튼과 비동기 진행 상태를 추가했다.
- 최대 20개 인기 보통주에서 이미 관찰 중인 종목을 빼고 70점·데이터 충실도·실적 추세·영업흑자·부채비율·최대 낙폭 기준을 통과한 5개를 선별한다.
- 일반 기업 점수로 왜곡될 수 있는 금융·지주 업종은 전용 기준을 만들기 전까지 자동 추천에서 제외한다.
- 추천 카드에 첫 번째 선정 근거와 확인할 위험 신호를 함께 표시한다.
- `/long-term`은 저장된 점수순으로 상위 장기 관찰 후보를 보여주고, 개별 분석 리포트는 종목 상세의 `장기분석` 탭에 배치했다.
- 국내 보통주를 검색하고 OpenDART 재무정보와 토스증권 1년 가격 데이터를 함께 분석하도록 구현했다.
- 성장성·수익성·재무안정성·가치지표·배당을 5개 관찰 항목으로 나누고, 데이터가 없는 항목은 0점 처리하지 않고 총점에서 제외한다.
- 점수를 S(90 이상)·A(80 이상)·B(70 이상)·C(60 이상)·D 랭크로 표현하고 의미 설명을 함께 표시한다.
- 분석 결과를 PostgreSQL에 저장해 24시간 재사용하며 후보 보드에 분석일과 공시 기준연도를 표시한다.
- 거래대금 상위 보통주 8개를 낮은 호출 속도로 자동 분석하고, 저장된 결과 중 점수가 높은 종목을 후보 보드에 추천한다.
- 자동 분석은 개발 기간 한국시간 매일 09:10에 실행하고, 실행 중에는 모든 주요 화면 상단에 흐르는 점검 안내를 표시한다. 정식 운영 전에는 04:30으로 복원한다.
- 장기분석 페이지를 `추천 관찰 후보`와 `내 관찰 후보` 탭으로 분리했다.
- 내 관찰 후보에는 하트 관심종목과 종목 상세 장기분석에서 직접 추가한 보통주를 함께 표시한다.
- 종목 상세 장기분석 탭에서 내 관찰 후보 추가·제거가 가능하며 미분석 후보는 상세 분석으로 연결한다.
- 상세 페이지의 단순 조회 분석 캐시와 자동선별 추천 목록을 별도 테이블로 분리해 조회한 종목이 추천 탭에 섞이지 않도록 했다.
- 최근 3개년 실적, 참고 PER·PBR, 1년 수익률·최대 낙폭, 긍정 근거와 위험 신호를 한 화면에 표시한다.
- 모든 주요 화면의 워크스페이스 내비게이션에서 장기분석 페이지로 이동할 수 있게 연결했다.
- 분석 계산·랭크 경계·일일 갱신 시각 단위 테스트를 추가하고 전체 테스트 101개 통과를 확인했다.

### 실제 시세 PAPER 전략·손익 개선

- PAPER 실행을 실제 현재가와 완료된 1분봉에 연결하고 조회 주기와 재주문 대기를 분리했다. 시세 오류·지연 때 가상 가격으로 대체하지 않는다.
- 손절·익절·추세 청산의 주문 대기를 제거하고 전략 관리 보유분 전체를 청산한다.
- 진입에 2봉 확인과 가격 추세 확인을 추가했다. 성과 개선 여부는 별도 검증이 필요하다.
- 실제 10개 종목의 30분봉 재현에서 모든 교차를 막던 이동평균 간격 대 왕복비용 비교를 제거했다. 비용은 체결가와 순손익에 반영한다.
- 전략 판단 화면에 종목별 매수 대기 이유를 표시하고 실행 시작·중지 이벤트를 거래 기록에 남긴다.
- 전략 관리 수량과 수동 거래를 분리하고, 수익률 분모를 누적 매수금액에서 최대 순투입자금으로 변경했다.
- 복사 전 실계좌 손익을 PAPER 손익에 섞지 않도록 복사 시점 가격을 모의 기준단가로 사용한다.
- 주문 이유·비용·청산손익을 영구 파일에 기록하고 화면 및 다운로드를 제공한다.
- 요청에 따라 최소 현금 비율을 0%, PAPER와 저장 DRY RUN 전략의 하루 주문 횟수를 무제한으로 반영했다. 기존 금액·손실 한도와 LIVE 전략 설정은 유지한다.
- 자세한 계산 기준과 제한은 [PAPER 전략 설명](PAPER_STRATEGY.md)을 참고한다.

### 시작 연결 상태·PostgreSQL 이전

- 로그인 화면 진입 시 PostgreSQL과 토스 API 토큰·계좌 연결 상태를 확인하도록 추가했다.
- 두 연결이 준비되기 전에는 로그인 버튼을 대기 상태로 두고 5초마다 자동 재확인한다.
- 서버 시작 시 토스 연결·종목 예열·실주문 대조 실패 원인을 로그에 남기도록 개선했다.
- 프로젝트 전용 수동 PostgreSQL `55432` 데이터를 백업하고 Windows 자동 시작 PostgreSQL `5432`로 이전했다.
- 이전 직후 복원용 덤프와 기존 데이터 폴더를 임시 보존했으며, 5432 동작 확인 후 개발 데이터와 구형 스크립트를 제거했다.
- 시작 직후 전체 종목 목록 예열을 제거하고 LIVE 계좌 갱신을 10초, 관심종목·스캐너를 60초로 완화했다.
- 토스 API가 429를 반환하면 `Retry-After` 또는 기본 30초 동안 후속 외부 요청을 차단해 반복 제한을 방지한다.
- 토스 요청을 직렬화하고 최소 간격을 적용했으며 반복 429는 30초·60초·120초 순으로 대기 시간을 늘린다.
- LIVE 페이지는 현재 보고 있는 자산·관심종목·스캐너 탭만 조회하고 숨겨진 탭의 주기 호출은 중단한다.

### PAPER 전략 조건 적용

- 저장 전략의 익절률과 손절률에 도달하면 PAPER 보유 수량을 모의 매도하도록 연결했다.
- 최대 보유일이 지나면 수익률과 관계없이 모의 매도하도록 연결했다.
- 한국 시간 기준 운영 시작·종료 시간 밖에서는 신규 모의 주문을 내지 않도록 했다.
- 종목별 체결 시각을 기준으로 재주문 대기시간이 지나기 전 주문을 차단하도록 했다.
- 전략별 하루 주문 한도 연결은 이번 작업에서 제외하고 기존 공통 위험 한도 검사는 유지했다.
- 익절·손절·최대 보유일·운영시간·재주문 대기 자동 테스트를 추가했다.
- 기존 전체 모의계좌 수익률은 유지하고 현재 선택 전략 대상 종목과 해당 주문 현금흐름만 계산하는 전략 수익률·손익 카드를 추가했다.
- 전략 밖 실제 보유종목과 이전 전략의 가격 변화는 새 전략 수익률에서 제외한다.

### 종목 상세 주문 패널

- 차트 옆에 일반 주문과 목표가 도달 주문을 입력하는 LIVE 주문 패널을 추가했다.
- 실제 주문을 보내지 않는 DRY RUN 검토 API를 연결했다.
- PIN 미인증 시 상세 화면에서 인증 팝업을 열고 인증 후 검토를 자동 재시도한다.
- 주문 가능 금액, 보유 수량, 투자 한도와 최소 현금 보유 비율을 검사한다.
- 최소 현금 규칙을 주문 전에 설명하고 검토 결과에 현재·주문 후·요구 비율을 표시한다.
- 향후 다중 사용자 확장을 고려해 LIVE 주문 기록을 사용자와 증권계좌에 귀속시키는 설계 원칙을 문서화했다.
- 검토 통과 후 주문 내용을 다시 보여주는 최종 확인 팝업을 추가했다.
- 확정한 DRY RUN 주문을 사용자·토스 계좌별 PostgreSQL 기록과 이벤트로 저장한다.
- `clientOrderId`를 이용해 재전송 시 같은 주문이 중복 저장되지 않도록 했다.
- 종목 상세 주문 패널에 최근 DRY RUN 주문 기록을 표시한다.
- LIVE 화면에 사용자별 DRY RUN 주문 관리 탭과 검사 결과 상세 보기를 추가했다.
- DRY RUN 주문 취소와 오늘 생성한 테스트 주문·이벤트 일괄 삭제 기능을 추가했다.
- 취소 주문은 행을 흐리게 하고 붉은 상태 배지와 취소 완료 문구로 구분했다.
- 기능 검증을 위해 투자 정책 한도는 임시 해제하되 실제 원화 주문 가능 금액과 매도 보유 수량 검사는 유지한다.
- 오늘 생성한 DRY RUN 테스트 기록은 당일 작업 종료 후 삭제하기로 했다.

### 실제 주문 연결 준비

- 토스증권 Open API 1.2.19 규격에 맞춘 국내주식 DAY 지정가 주문·주문 상세 조회·취소 어댑터를 추가했다.
- `LIVE_TRADING_ENABLED=false` 안전 잠금을 기본값으로 두고, 국내 6자리 종목·정수 수량·지정가·멱등 `clientOrderId`만 허용했다.
- 실제 주문 준비 상태를 확인하는 읽기 전용 API를 추가했다.
- 최종 확인 화면에서 실제 주문을 구분하고 이중 확인한 국내주식 DAY 지정가만 토스에 전송하도록 연결했다.
- 실제 주문에는 DRY RUN 한도 완화가 적용되지 않으며 PIN·현금·보유 수량·모든 투자 정책을 다시 검사한다.
- 전송 전 DB에 주문을 선점해 중복 제출을 막고 토스 주문 ID·접수 상태·상태 변경 이벤트를 저장한다.
- 주문 관리에서 실제 주문 상태를 읽기 전용으로 동기화하고 미체결 실제 주문 취소를 지원한다.
- 통신 결과가 불확실하면 `UNKNOWN`으로 기록하고 자동 재전송하지 않도록 했다.
- 실제 소액 시험으로 `487240` 1주 DAY 지정가 매도 주문의 전송·전량 체결·DB 상태 저장·보유 수량 반영을 확인한 뒤 안전 잠금을 다시 비활성화했다.
- `487240` 1주 40,000원 지정가 매도를 1분간 미체결 상태로 유지한 뒤 실제 취소해 체결 수량 0주·`CANCELED`·보유 수량 불변을 확인했다.
- LIVE PIN 인증 완료 버튼을 초록색으로 표시하고 인증 만료 시 잠금 상태 색상으로 복귀하도록 개선했다.

### 실제 주문 복구·대조

- 서버 시작 시 DB의 실제 주문을 토스 OPEN·CLOSED 주문 목록과 자동 대조한다.
- 체결 수량·평균 체결가·체결 금액·수수료·세금과 마지막 동기화 시각을 PostgreSQL에 저장한다.
- 대조 결과를 `MATCHED`, `NEEDS_REVIEW`, `ERROR`로 관리하고 주문 관리 화면에 표시한다.
- 취소 직후 개별 주문 상세가 이전 상태를 반환하는 경우를 발견해 OPEN·CLOSED 주문 목록을 복구 기준으로 사용하도록 수정했다.
- 재시작 시험에서 실제 체결 주문과 취소 주문이 각각 `FILLED`, `CANCELED`로 복원되고 수수료까지 일치하는 것을 확인했다.

### 수동·자동 주문 구분

- 실제 주문에 서버 관리형 `order_source`를 추가해 `MANUAL`과 `AUTO`를 구분한다.
- 기존 실제 주문은 모두 수동 주문으로 이전하고 주문 관리 화면에 수동·자동 출처를 표시한다.
- AUTO 순체결 수량을 종목별로 계산해 보유 종목을 `자동관리`와 `기존·수동` 수량으로 나눠 표시할 기반을 추가했다.
- 사용자 요청 본문에서는 주문 출처를 지정할 수 없고 향후 자동매매 엔진만 서버 내부에서 `AUTO`를 기록할 수 있다.

- 모든 주요 화면에서 접근할 수 있는 `/settings` 통합 설정 페이지를 추가했다.

- 모의매매 페이지를 처음 열 때 실제 원화 현금과 국내 보유종목을 확인 없이 자동 복사하도록 개선했다. 이미 준비된 모의계좌는 페이지 재방문 시 덮어쓰지 않는다.
- 현재 국내 거래대금 상위 종목과 저가 인기 종목을 바탕으로 인기·가성비 프리셋의 DRY RUN/LIVE 테스트 전략 4개를 추가했다. 저장 전략은 모두 비활성 상태다.
- 모의 자동매매의 일시정지와 긴급 중지 버튼에 PC·모바일용 설명 툴팁을 추가하고 역할이 드러나는 명칭으로 정리했다.
- DRY 인기·가성비 프리셋을 빠른 검증용 2/3 이동평균, 2초 판단 주기, 하루 20회 주문 한도로 조정했다. LIVE 프리셋의 보수적인 설정은 유지한다.
- 모의매매 실행 영역에 테스트용 DRY 프리셋이 2초 판단 주기와 2/3 이동평균을 사용하는 빠른 검증 설정임을 안내했다.
- 현금이 적은 현재 테스트 기간에는 PAPER 매수의 최소 현금 30% 검사만 임시 제외한다. LIVE 주문 한도와 나머지 PAPER 투자 한도는 유지한다.
- 모의 수익률과 총손익에 상승·하락 색상, 방향 기호와 양수 부호를 적용해 손익 방향을 바로 구분할 수 있게 했다.
- 빠른 PAPER 반복 검증 중에는 일일 주문 횟수 제한도 임시 제외한다. LIVE 제한은 유지하며 정식 완료 전 복원 항목으로 기록했다.
- 모의 주문 기록에 초 단위 주문 시간을 추가해 매수·매도 발생 시점을 확인할 수 있게 했다.
