# 바이브 코딩 학습 노트

제품 요구사항과 운영 문서에 섞여 있던 개인 학습 메모를 별도로 보관합니다. 이 문서는 앱의 현재 동작을 정의하지 않습니다.

## 기본 개념

바이브 코딩은 만들고 싶은 기능을 자연어로 설명하고, AI가 만든 결과를 사람이 검토·수정하며 개발하는 방식입니다.

- AI의 역할: 구현, 디버깅과 테스트 보조
- 사람의 역할: 요구사항 결정, 결과 검증, 위험 판단과 최종 승인

전통적인 개발의 요구사항 분석·설계·구현·테스트 과정이 사라지는 것은 아닙니다. AI가 구현 속도를 높이더라도 명확한 요구사항, 코드 검토와 실제 동작 확인은 여전히 필요합니다.

## 요청을 구체화하는 단계

- 제로샷: 배경 문서 없이 대화로 요구사항을 설명
- 원샷: 한 번에 실행할 수 있는 짧고 명확한 요구사항 제공
- 퓨샷·문서 기반: PRD, 예시와 완료 조건을 함께 제공

규모가 커질수록 현재 상태, 안정적인 요구사항, 가까운 작업과 보류 아이디어를 분리하면 AI가 오래된 계획을 현재 요구로 오해하는 일을 줄일 수 있습니다.

## 이 프로젝트의 개발 환경

- Windows와 PowerShell
- Python, FastAPI와 PostgreSQL
- VS Code 또는 Codex를 이용한 코드 작성·검토
- 토스증권 Open API와 선택형 OpenDART 연동

토스증권 API 사용에는 토스증권 가입, PC 웹 로그인, 사용 IP 등록과 Open API 키 발급이 필요합니다. 키와 DB 암호는 `.env`에만 저장하고 Git에 포함하지 않습니다.

## 안전하게 AI와 금융 기능 만들기

- PAPER와 LIVE를 화면과 서버에서 모두 구분합니다.
- 외부 API 실패를 성공처럼 처리하지 않습니다.
- 실제 주문은 명시적인 사용자 확인과 여러 안전장치를 거칩니다.
- 계산 기준과 임시 개발 예외를 문서에 남깁니다.
- 생성된 코드보다 테스트 결과와 실제 브로커 상태를 우선합니다.
