# 보류 기능

기준일: 2026-10-04

지금 구현하지 않을 아이디어와 미확정 설계를 잊지 않기 위한 목록입니다. 기본 기능은 대부분 구현했으므로 이 목록을 채우기 위해 새 기능을 추가하지 않습니다. 착수할 때 범위와 완료 조건을 정해 [ROADMAP.md](ROADMAP.md)로 옮깁니다.

## PAPER 데이터와 전략 연구

주간 프리셋 갱신·후보 저장과 PAPER 계좌 자산·주문·관리 범위·마지막 선택 전략 저장은 구현되어 보류 목록에서 제외했습니다. 프리셋은 별도 강제 갱신 버튼 대신 주간 첫 미리보기에서 갱신합니다. 현재 동작은 [CURRENT_STATE.md](CURRENT_STATE.md)와 [PAPER_STRATEGY.md](PAPER_STRATEGY.md)를 참고합니다.

판단 이력 조회 화면은 추가하지 않는 것으로 결정했습니다. 학습용 DB 기록과 내부 조회는 유지하며 사용자는 현재 판단·주문 기록만 확인합니다.
- 재시작 전후 전략 성과 기준선·실행 구간을 이어서 비교하는 저장 방식 검토. 자산·주문·마지막 전략 복원과 자동 실행 복구는 별개의 범위로 다룬다.
- 장애 후 실행 복구 정책 검토. 현재 재시작 시 정지 상태로 복원하며 사용자가 전략 시작을 누른다. 자동 재개는 아직 제품 정책으로 결정하지 않았다.
- 장기간 축적한 시장·전략 결과를 이용한 성과 분석
- 전략 버전별 비교, 구간별 백테스트와 재현 가능한 리플레이
- 충분한 데이터가 모인 뒤 전략 개선 제안 또는 제한된 자동 튜닝

원본·판단 데이터 수집과 품질 검사는 구현되어 데이터를 누적 중입니다. 모델 학습·성과 판단에는 수집 기간, 비용 포함 백테스트, 과최적화 방지와 변경 승인 절차가 필요합니다.
학습과 구현 순서는 [머신러닝 학습 과정](machine-learning/README.md)에 별도로 정리합니다.

## LIVE 자동매매

- PAPER에서 승인한 전략의 LIVE 실행
- LIVE 자동매매 워커의 장중 재시작 복구와 부분 체결·취소·정정 처리 확장. 현재 수동 주문의 저장·미확정 주문 재시작 대조와 구분한다.
- 종목·전략별 손실 차단과 전체 비상 정지
- 실행 전 시뮬레이션 결과와 운영 체크리스트 강제

현재 LIVE는 계좌 조회와 사용자가 확인하는 수동 주문까지만 운영 범위입니다.

## 사용자와 운영

### 휴대폰 연결 앱 (구현 보류)

2026-10-03 사용자 결정: 개인용 로컬 웹앱을 기반으로 집 컴퓨터가 켜져 있을 때 외출 중 휴대폰에서 상태를 확인하고 필요하면 정지하는 앱을 이후 검토한다. 지금은 계획만 기록하며 앱 개발이나 외부 네트워크 개방은 진행하지 않는다.

- 실행 장소: 집 컴퓨터에서 시세 수집·전략 실행·DB 저장을 담당한다. 컴퓨터·프로그램·DB·인터넷 연결이 유지되어야 하며, 절전·최대 절전 시에는 정상 실행을 전제하지 않는다.
- 휴대폰 역할: 실행 상태, 최근 시세 수신·전략 판단 시각, 주문·손익과 중요 알림을 확인한다. 증권 API 키는 실행 컴퓨터에 보관하고 휴대폰으로 전달하지 않는다.
- 원격 정지: 신규 매수만 중단하고 보유분 익절·손절 관리를 유지하는 기능과, 자동 매수·매도를 모두 중단하는 기능을 구분해 검토한다. 보유 종목은 정지만으로 매도하지 않는다. 이미 접수된 미체결 주문 취소는 별도의 동작으로 다룬다. 이는 후속 요구사항이며 현재 LIVE 자동매매 구현 완료를 뜻하지 않는다.
- 확인 기준: 정지 명령을 보냈다는 이유만으로 완료를 표시하지 않는다. 실행 컴퓨터가 실제로 처리한 응답을 확인한 뒤 정지 완료를 표시한다. 응답이 없으면 정지 확인 안 됨으로 안내한다.
- 연결 끊김: 컴퓨터가 꺼졌거나 연결이 끊겼을 때도 앱을 열어 마지막 확인 시각과 연결 끊김을 표시한다. 저장된 과거 상태를 현재 실행 중인 상태로 표시하지 않는다.
- 착수 전 결정: 네이티브 앱·설치 가능한 웹앱 중 형식, 개인용 원격 연결 방식과 인증·암호화, 알림 방식, 정지 대상 계좌·전략과 미체결 주문 처리 범위를 정한다.
- 운영 전제: 유료 원격 서버 이전과 토스 로그인은 보류한다. 재시작 후 자동 재개 정책은 별도로 결정하며 앱 연결 때문에 자동 재개를 켜지 않는다.

현재 작업을 마친 뒤 사용자와 설계를 결정하고 구현 범위·검증 조건을 정한다.

### 설정 → 계정: 남은 연결·배포 설계 (보류)

사용자별 API 연결 등록·변경과 연결·모의계좌·실행 상태의 소유 분리는 구현되었습니다. 기존 관리자 키는 `.env`, 새 키는 Windows 암호화 로컬 파일을 사용하며 DB에는 키를 저장하지 않습니다. 현재는 아이디마다 한 증권 연결과 기존 모의계좌·실험계좌를 제공하며 같은 실제 계좌의 중복 연결·다른 실제 계좌로의 교체는 막습니다. 모의계좌 두 칸은 실제 계좌 두 개를 뜻하지 않습니다.

남은 검토 범위는 다음과 같습니다.

- 첫 설치·키 유실 시 로그인과 계정 설정 접근은 구현했다. FOLIO.cmd의 가상환경·패키지 준비, DB 서비스 시작과 최초 관리자 생성 안내도 구현했다. Python·PostgreSQL 설치 및 최초 DB 생성은 현재 설치 안내를 따르며 완전한 설치 프로그램은 별도로 검토한다.
- 연결 해제·로컬 키 삭제 시 남길 자산·주문 기록, 실행·미체결 주문 처리와 사용자 확인 범위
- 설치형 프로그램 또는 앱 배포 결정 후 프로그램 설치 위치와 별개인 사용자 설정 폴더로 키 보관 위치 옮기기. 배포 파일에 제작자 API 키를 넣지 않기
- Windows 사용자·컴퓨터 이동 시 키 재등록 안내와 DB·설정·로컬 파일 백업 범위 정하기
- 토스 로그인은 보류. 추후 도입을 결정하면 사이트 로그인 신원과 증권 API 조회·주문 권한을 별도로 확인하고 연결하기
- 여러 실제 계좌·특수 계좌·여러 증권사 지원은 현재 범위 밖. API가 계좌 목록을 반환한다는 이유만으로 사용 가능하다고 가정하지 않고 필요할 때 지원 범위를 다시 확인하기

공개 회원가입과 유료 서버 운영은 현재 개인용 방향에서 확장하지 않습니다. 현재 구현·저장 기준은 [CURRENT_STATE.md](CURRENT_STATE.md)와 [DATABASE.md](DATABASE.md)를 참고합니다.

### 시스템 설정

- 시스템 설정 확장 시 기본 프리셋의 최대 종목 수를 별도 설정으로 제공하기. 현재는 최대 10개로 고정하며, 시장·예산 조건을 통과한 후보를 거래대금 순위로 정렬한 뒤 상한까지만 담는다. 설정 변경은 이후 미리보기·새 전략 생성에 적용하고 기존 저장 전략은 자동 변경하지 않기.

### 첫 사용자를 위한 화면 안내·가이드북 (장기 보류)

주요 기능과 화면 구성이 완성되고 안정된 뒤 진행합니다. 당장의 구현 작업이 아니라, 처음 접하는 사람이 각 항목의 의미와 사용 순서를 이해하도록 돕는 후속 작업입니다.

- 첫 실행 또는 페이지 첫 방문 때 선택적으로 시작하는 단계별 안내 투어
- 설명하는 버튼·카드·영역을 강조하고, 짧은 설명을 읽은 뒤 `다음`으로 이동하는 흐름
- `이전`, `건너뛰기`, `닫기` 제공 및 안내 완료 여부 저장. 도움말에서 다시 실행 가능
- 페이지별 기능과 용어를 간단히 정리한 가이드북·도움말 제공
- 모의매매는 계좌 종류, 전략 선택(즉시 적용)·실행 순서, 보유분 관리 범위, 판단·주문 기록, 일시정지·긴급 중지의 의미를 안내
- 안내 중 실제 설정 변경이나 주문·전략 실행을 자동으로 수행하지 않기
- 작은 화면과 키보드 사용에서도 강조 영역·설명·이동 버튼을 확인할 수 있도록 구성

착수할 때 전체 페이지의 안내 범위와 완료 조건을 정하고 로드맵으로 옮깁니다.
