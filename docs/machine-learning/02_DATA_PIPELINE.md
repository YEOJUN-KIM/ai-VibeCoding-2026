# 2. 데이터 수집과 학습 데이터

## 원본 데이터 우선

머신러닝 특징을 바로 저장하지 않고 API에서 받은 원본과 수집 시각을 먼저 저장합니다. 계산식이 바뀌어도 원본으로 다시 생성할 수 있어야 합니다.

최소 데이터는 다음과 같습니다.

- 종목별 완료된 1분봉 OHLCV
- 코스피·코스닥과 가능한 업종 지수
- 환율과 해외 시장 지표
- 뉴스 제목, 출처, 게시 시각, 최초 수집 시각
- 공시 종류와 게시 시각
- 당시 전략 신호, 주문, 비용과 이후 결과

## 시간 필드

각 레코드는 적어도 세 시간을 구분합니다.

- `event_at`: 시장 체결이나 뉴스 게시가 발생한 시각
- `available_at`: 자동매매 프로그램이 그 정보를 사용할 수 있게 된 시각
- `collected_at`: 프로그램이 실제로 저장한 시각

오전 10시 예측에는 `available_at <= 10:00`인 데이터만 사용할 수 있습니다. 이후 수정된 기사나 장 마감 뒤 확정된 값을 오전 판단에 넣으면 미래 데이터 누출입니다.

## 데이터 품질 검사

- 종목·시각 중복 여부
- 1분봉 시간 순서와 누락 구간
- 가격·거래량의 음수 또는 0 값
- 휴장일과 거래정지 구분
- 수정주가와 액면분할 처리 여부
- 뉴스 게시 시각의 시간대
- API 장애 시 마지막 값을 새 값처럼 반복 저장하지 않았는지

## 첫 수집 범위

처음에는 모든 종목을 무리하게 모으지 않습니다. PAPER 전략 후보 종목과 대표 지수로 시작해 API 호출량과 저장 품질을 확인한 뒤 범위를 넓힙니다.

첫 학습 전에는 최소한 여러 시장 국면을 포함하는 기간이 필요합니다. 데이터가 적을 때는 모델 성능을 주장하지 않고 파이프라인과 백테스트 재현성을 포트폴리오 결과로 삼습니다.

## 현재 구현: 1분봉 원본 저장

2026-10-02에 첫 수집 파이프라인을 구현했습니다.

- `ml_collection_runs`: 언제 어떤 종목을 몇 개 요청했고 성공·실패했는지 기록
- `ml_raw_candles`: 토스에서 받은 완료 1분봉과 세 가지 시각을 원본 형태로 보존
- `(source, symbol, interval, event_at)` 기본키로 재수집 중복 방지
- `collection_run_id`로 각 원본 행의 수집 실행 추적
- `available_at` 조건이 있는 조회 함수로 미래 데이터 누출 방지
- 누락 구간, 5분 초과 수집 지연, 거래량 0 통계 출력

가격 특징이나 정답을 이 테이블에 덮어쓰지 않습니다. 이후 가공 데이터는 별도 테이블이나 파일로 만들고 생성 기준과 원본 범위를 기록합니다.

### 직접 수집하기

기본 `WATCH_SYMBOLS`에 대해 종목별 최근 200개를 수집합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\collect-ml-data.ps1
```

종목과 개수를 지정할 수도 있습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\collect-ml-data.ps1 `
  -Symbols "005930,000660" -Count 200
```

결과의 주요 항목은 다음과 같습니다.

- `inserted_rows`: 새로 저장한 봉 수
- `duplicate_rows`: 기본키가 같아 추가하지 않은 기존 봉 수
- `errors`: 종목별 API·검증 오류
- `quality`: 종목별 누락·지연·거래량 통계

처음 과거 봉을 가져오는 백필에서는 오래된 봉의 `delayed_over_5m`가 큰 것이 정상입니다. 이후 정시 수집분은 이 값이 갑자기 늘어나는지 감시합니다.

### 실제 첫 검증 결과

2026-10-02 삼성전자와 SK하이닉스의 완료 1분봉을 수집했습니다.

- 첫 실행: 36건 저장, 누락 구간 0건, 오류 0건
- 동일 구간 재실행: 0건 추가, 중복 36건으로 판정
- 저장된 시각 범위: 한국시간 11:17~11:34

## 학습 테이블 예시

한 행은 한 종목의 한 판단 시점입니다.

| 필드 | 의미 |
|---|---|
| `decision_at` | 예측 시각 |
| `symbol` | 종목 코드 |
| `return_1m`, `return_5m` | 직전 구간 수익률 |
| `ma_gap`, `ma_slope` | 이동평균 간격과 기울기 |
| `volume_ratio` | 평소 대비 거래량 |
| `volatility_20m` | 최근 변동성 |
| `market_return` | 같은 시점 국내 지수 흐름 |
| `news_count_60m` | 최근 1시간 관련 뉴스 수 |
| `future_net_return_20m` | 비용 차감 후 정답 |

## 완료 조건

- 같은 기간을 다시 수집해도 중복되지 않는다.
- 원본과 가공 데이터의 생성 관계를 추적할 수 있다.
- 데이터 누락·지연·오류 통계가 출력된다.
- 지정한 과거 시점에서 당시 사용 가능했던 데이터만 조회할 수 있다.

## 다음 구현 순서

1. 수집 주기를 1분으로 운용하고 장 마감 후 일일 품질 보고서를 남긴다.
2. PAPER 전략의 판단 시점과 매수 거절 사유를 원본 데이터에 연결한다.
3. KOSPI·KOSDAQ 대표 지표를 같은 시간 구조로 저장한다.
4. 충분한 기간이 쌓인 뒤 특징·정답 데이터셋을 원본에서 생성한다.
