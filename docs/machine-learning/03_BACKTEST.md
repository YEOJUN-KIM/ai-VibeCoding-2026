# 3. 비용 포함 백테스트

문서 상태 (2026-10-04): 기준선 재생·비용 반영·결과 저장은 구현했습니다. 첫 하루 일부 자료 실행은 확인했으나 여러 거래일 검증과 모델 성과 비교는 남았습니다. 실제 진행은 [구현 현황](CURRENT_PROGRESS.md)을 따릅니다.

## 백테스트가 먼저인 이유

머신러닝 모델에는 비교 대상이 필요합니다. 현재 이동평균 전략, 단순 보유와 거래하지 않는 경우를 기준선으로 둡니다.

## 백테스트 입력

- 시작·종료일과 대상 종목
- 봉 주기와 이동평균 설정
- 초기 자금과 주문 수량 규칙
- 수수료, 세금과 슬리피지
- 운영 시간, 재진입 대기와 청산 조건
- 전략 코드 버전과 데이터 버전

## 평가 지표의 목표 범위

아래는 단계적으로 갖출 평가 기준입니다. 현재 저장되는 결과와 미구현 그래프·모델 비교·시장 국면 분석은 하단의 첫 구현 설명에서 구분합니다.

| 분류 | 지표 |
|---|---|
| 수익 | 총 순손익, 수익률, 거래당 평균 순손익 |
| 위험 | 최대 낙폭, 손실 연속 횟수, 일별 손실 분포 |
| 거래 | 거래 횟수, 승률, 평균 이익, 평균 손실, 손익비 |
| 비교 | 이동평균 기준, 단순 보유, ML 적용 전략 |
| 안정성 | 월별·종목별·시장 국면별 성과 |

## 시간 분리

데이터는 시간순으로 나눕니다.

```text
학습 기간 → 설정 조정에 사용
검증 기간 → 모델과 기준값 선택에 사용
최종 시험 기간 → 마지막 한 번의 성능 확인에 사용
```

최종 시험 결과를 보고 설정을 다시 바꾸면 그 기간도 검증 기간이 됩니다. 새 최종 시험 기간을 확보해야 합니다.

## 재현성

완성된 실험에서는 다음 정보를 함께 보존해야 합니다. 현재 결과 파일의 범위는 하단 실행 설명을 따릅니다.

- 실행 ID와 실행 시각
- Git 커밋 또는 코드 식별자
- 데이터 조회 범위와 버전
- 전략·비용·모델 설정
- 거래 내역 전체
- 요약 지표와 그래프

## 완료 조건

- 같은 입력으로 같은 주문과 손익이 나온다.
- 미래 봉을 참조하면 테스트가 실패한다.
- 수수료·세금·슬리피지를 0으로 둔 결과와 실제 가정 결과가 구분된다.
- 기준 전략과 모델 전략을 같은 데이터·체결 규칙으로 비교한다.

## 첫 구현과 실행 (2026-10-02)

저장된 원본을 읽기 전용으로 조회하고 기존 `MovingAverageEngine`·`PaperBroker`를 메모리에서 재사용하는 첫 기준선 실험을 추가했습니다. 실행 중인 PAPER 계좌나 전략 설정을 변경하지 않습니다.

```powershell
# 저장된 모든 종목: 10/40 이동평균, 1회 30만원, 초기 현금 1,000만원
.\.venv\Scripts\python.exe -m auto_trader.ml.backtest `
  --start 2026-10-02 --end 2026-10-02 `
  --output artifacts/ml/generated/backtest-20261002

# 저장 전략의 설정·대상 사용 (전략 ID는 DB에 존재하는 값)
.\.venv\Scripts\python.exe -m auto_trader.ml.backtest `
  --strategy-id 15 --start 2026-10-02 --end 2026-10-02 `
  --output artifacts/ml/generated/backtest-20261002-popular
```

`report.json`에는 설정, 입력·코드 해시, Git 커밋, 거래 내역, 자산 곡선, 자료 범위와 누락 대상을 기록합니다. `input.json`은 조회 시점의 입력 스냅샷, `summary.md`는 비교표, 각 `*-equity.csv`는 자산 시계열입니다. 시작·종료일은 봉 발생일이 아니라 한국시간 `available_at` 기준입니다. 날짜마다 출력 폴더를 바꾸면 이전 결과를 보존할 수 있습니다.

### 체결과 비교 기준

- `available_at` 순서로 과거 봉을 공개합니다. 미완료 봉은 거절하고 2분 넘게 지연된 최신 봉은 매매를 유발하지 않습니다. 과거 백필은 이동평균 준비에만 사용합니다.
- 기본 체결은 신호 수집 시각보다 **뒤에 시작된 봉의 시가**입니다. 같은 날 2분 이내의 거래량이 있는 봉만 사용하며, 신호 시각에 이미 지나간 시가는 쓰지 않습니다. 주문 수량은 신호 시각에 고정하고 체결 시 잔액·한도를 재확인합니다. 마지막 미체결 신호는 강제 체결하지 않습니다. `--execution close`로 이전 종가 체결 가정도 비교할 수 있습니다. 실제 PAPER 체결을 그대로 재현하는 방식은 아닙니다.
- 진입·청산·수량 계산·재진입 대기·전략 주문 한도는 기존 엔진을 재사용합니다. 백테스트는 기본 위험 프리셋(1회 100만원, 종목별 200만원, 전체 700만원, 최소 현금 30%, 일일 손실 50만원, 수익 목표 100만원)을 메모리에 적용합니다. `--no-risk`로 한도 없는 비교가 가능하며 실행 중인 계좌의 설정은 변경하지 않습니다. 호가·부분 체결·거래량 대비 주문 규모는 반영하지 않습니다.
- 단순 보유는 같은 종목별 매수 예산으로 최초 신선한 관측에서 매수합니다. 같은 현금으로 출발하지만 투자 비중이나 보유 시간은 전략과 다를 수 있습니다.
- 마지막 보유분을 강제로 매도하지 않고 가상 청산 비용을 뺀 자산으로 평가합니다. 거래별 승률은 완료된 매도 주문만 대상으로 하며 미청산 손익은 포함하지 않습니다.
- 비용을 0으로 둔 전략도 별도 실행합니다. 비용이 수량·청산 판단에 영향을 주므로 두 실행의 거래가 반드시 같지는 않습니다.

첫 전체종목 실행은 10종목·2,376봉에서 비용 포함 -10,580.48원(-0.1058%), 비용 0일 때 +1,950원, 단순 보유 +4,020.93원을 기록했습니다. 대상 데이터는 하루 오후 일부이며 성능 검증 결과가 아닙니다. 저장 전략 15의 대상 10종목 가운데 데이터가 있는 것은 삼성전자 하나여서 별도 실험도 전체 전략 성적으로 해석할 수 없습니다.

위 최초 결과는 `close`·위험 한도 미적용 버전의 기록입니다. 현재 기본값인 `next_open`·위험 한도 적용 결과와는 분리해 비교합니다. 미래 값 변경 시 과거 주문·자산 불변, 백필 거래 차단, 비용 반영, 재현성과 DB 미변경을 포함한 테스트를 추가했습니다. 여러 거래일의 안정성 분석, 모델 비교, 호가·부분 체결 모델·그래프는 후속 작업입니다.

### 데이터 누적 중 점검

```powershell
# 누적된 전체 데이터를 같은 기본 설정으로 실행; 매번 별도 결과 폴더 생성
.\scripts\run-ml-backtest.ps1

# 특정 기간 또는 저장 전략
.\scripts\run-ml-backtest.ps1 -Start 2026-10-02 -End 2026-10-02 -StrategyId 15
```

요약에 종목별 자료 시작·끝, 중간 누락과 저장된 품질 보고서 상태를 표시합니다. 누락은 관측 구간 내부 통계이며 휴장·거래정지를 자동 판별하거나 장 전체 수집을 보장하는 수치가 아닙니다. 날짜별 `*-daily.csv`는 계좌를 매일 초기화하지 않고 누적 운용한 자산의 일별 변화이며, 일별 합계는 총손익과 일치합니다.

서버는 계속 켜두고 장 마감 후 품질 보고서를 확인합니다. 수집기는 기존 `WATCH_SYMBOLS`를 사용하므로 새 전략 종목이 포함되는지 별도로 확인해야 합니다. 백테스트는 예약 실행하지 않으며 위 스크립트로 필요할 때 실행합니다. 자동 수집과 백테스트는 서로 독립적입니다.
