# 머신러닝 자동매매 구현 현황

최신 확인일: **2026-10-30**. 수집 파이프라인은 운영·안정화 중이며 V1 수집 안정화와 V2 품질 의미·백테스트 날짜 선택 보수를 완료했습니다. 아래 2026-10-02 건수·실험 결과는 과거 이력으로 구분합니다.

이 문서는 머신러닝 자동매매 프로젝트에서 지금까지 구현하고 실제로 확인한 내용을 한곳에 정리합니다. 세부 설계와 실행 명령은 각 단계 문서를 참고합니다.

## 현재 단계

- 데이터 수집 파이프라인: 운영·안정화 및 다일 데이터 누적 중.
- V1 수집 안정화: 완료. 제한된 chart GET retry, 실제 수신 시각, opening/final reconciliation 유지.
- V2 보수: 완료. 최종 원천 부재와 수집 gap을 구분하고, 백테스트 날짜 선택을 KST `event_at` 기준으로 수정했습니다. replay는 계속 `available_at`을 사용합니다.
- 10/28 재생성 품질: raw missing 6, provider absent 6, collection gap 0, unverified 0. **data completeness PASS / collection health WARN**입니다. 09:01~15:30은 22종목 각 390개, 지수 각 390개입니다.
- 10/15·10/16·10/21 재검사: 실제 원천 봉 2,947개를 추가 수신 시각으로 백필했습니다. 기존 RAW 35,234개와 전략 17·22개 대상의 불변을 확인했습니다.
- ML Dataset 구성·실제 모델 학습: **아직 시작 전**. 다일 데이터의 시점·session 선택을 먼저 설계할 단계입니다.

검증은 Python **339개**, JavaScript **22개** 통과입니다. 실행 중인 장중 서버는 유지했으며, 자동 품질 워커의 V2 코드는 다음 정상 서버 재시작부터 적용됩니다. 과거 날짜의 품질 보고서는 수동 재생성까지 검증했습니다. 세부 수치와 제한은 [수집 안정화 V1/V2](COLLECTION_STABILITY.md), 날짜 선택은 [백테스트 설명](03_BACKTEST.md)을 참고합니다.

### 2026-10-12 운용 준비 이력

2026-10-12 운용 준비: 기존 수집 10종목과 저장 전략 두 개의 대상을 합쳐
`데이터 축적 · 22종목` 모의 전략을 저장하고, 이 PC의 `WATCH_SYMBOLS`도 같은
22종목으로 맞췄습니다. 10/40 이동평균, 종목당 1회 30만원, 익절 4%·손절 2%,
최대 보유 3일, 운영 09:00~15:30(KST), 일일 주문 한도 30회·재진입 대기 60분을
사용합니다. 실제 판단 시간에는 시장 캘린더 제한도 적용됩니다. 설정·DB 저장은
다른 PC로 자동 이동하지 않습니다. 서버 재시작 후에는 실험 모의계좌에서 이
전략을 선택하고 직접 시작해야 하며, 원본 수집은 전략 정지 중에도 계속됩니다.
전략 대상 상한은 30종목으로 확장했습니다. 아래 10월 2일 건수는 과거 기록입니다.

- 1단계 개발 환경 구성: 완료
- 2단계 데이터 수집 파이프라인: 운영 중, V1/V2 보수와 과거 gap 복구 완료
- 3단계 비용 포함 백테스트: 기준선 CLI 구현, event-date 선택과 availability replay 분리 검증 완료; 모델 성과 비교는 후속
- 4단계 첫 머신러닝 모델: Dataset 구성과 검증 설계 이후 진행

현재 목표는 PAPER 자동매매를 실행하면서 학습에 필요한 원본 데이터와 전략 판단을 안정적으로 쌓는 것입니다. 아직 수집 기간이 짧으므로 이 데이터만으로 모델 수익성을 판단하지 않습니다.

## 기본 기능과 후속 구현의 구분

계정·증권 연결·조회 화면·모의매매·휴장일 연동·간편 실행 등 사이트의 기본 기능은 대부분 구현했습니다. 지금은 데이터 축적과 실제 운용 확인에 집중합니다. 데이터가 준비되면 자료 결합·학습 정답 생성·다일 백테스트·모델 학습·실시간 모의 판단 연결을 이어서 구현·검증합니다. 실제 자동매매는 그 이후의 별도 단계이며 현재 수동 주문 기능과 구분합니다.

모의매매의 시장 캘린더 제한과 원본 수집 워커의 예약 일정은 별개입니다. 원본은 서버가 켜져 있으면 전략 정지 중에도 수집하고, 전략 판단은 전략 실행 중 유효한 거래 시간과 시세 조건에서만 생성합니다. 초기 5~20거래일 확보는 연구 시작 목표이며 모델 성과를 보장하는 기준이 아닙니다.

## 구현한 기능

### 1. 재현 가능한 개발 환경

- 프로젝트 전용 Python 가상환경과 머신러닝 패키지 구성
- Windows 설치·실행 방법 문서화
- 환경 변수 예시와 PostgreSQL 연결 설정 정리

자세한 내용: [01_ENVIRONMENT.md](01_ENVIRONMENT.md)

### 2. 종목 1분봉 수집

- `WATCH_SYMBOLS` 종목의 완료된 1분봉 OHLCV를 PostgreSQL에 저장
- 서버 실행 중 평일 09:01:02~15:31:02 KST에 매분 자동 수집
- 최근 구간을 다시 요청해 일시적인 API 장애 뒤 누락을 보충
- 기본키로 중복 저장 방지
- 수집 실행별 신규·중복·오류 건수 기록

저장 테이블: `ml_raw_candles`, `ml_collection_runs`

### 3. 국내 시장 지표 수집

- KOSPI와 KOSDAQ 완료 1분봉 수집
- 종목 수집과 같은 주기로 자동 실행
- 종목 봉과 분리해 PostgreSQL에 원본 보존

저장 테이블: `ml_market_indicator_candles`

### 4. 환율과 미국 시장 지표 수집

- 토스증권 USD/KRW 환율 저장
- SPY, QQQ, DIA, VIXY, IEF 일봉을 미국 시장·변동성·국채 대용 지표로 저장
- 서버 시작 시 즉시 한 번 수집
- 평일 08:10과 13:10 KST에 자동 수집
- FRED의 S&P 500, NASDAQ Composite, DJIA, VIX, 미국 10년물 금리도 수집 시도
- FRED 장애가 발생해도 토스 대용 지표와 PAPER 자동매매는 계속 동작
- 같은 기준일의 수정값을 덮어쓰지 않고 버전별 보존

저장 테이블: `ml_macro_observations`

2026-10-02 확인 당시 FRED 요청은 이 환경에서 시간 초과가 발생했습니다. 정확한 FRED 지표는 예약 실행마다 다시 시도하도록 구현되어 있습니다. 현재 성공 여부는 실행 로그·품질 보고서에서 확인합니다.

### 5. PAPER 전략 판단 기록

- 새 완료 봉마다 전략의 `DATA_WAIT`, `WAIT`, 매수·매도 체결 및 제한 결과 저장
- 현재가, 이동평균, 추세, 보유 수량, 현금, 총자산과 판단 이유 보존
- 주문 루프와 분리한 메모리 큐에서 묶음 저장
- DB 장애 시 다음 주기에 재시도
- 판단 고유키로 재시도 중복 방지

저장 테이블: `ml_strategy_decisions`

기존 DB의 부분 고유 인덱스 때문에 판단 저장이 실패하던 문제도 수정했습니다. 현재 PAPER 판단이 PostgreSQL에 정상 누적됩니다.

### 6. 데이터 품질 보고서

- 평일 15:40 KST에 당일 품질 보고서 자동 생성
- 종목·지수 봉 누락, 5분 초과 지연, 거래량 0 집계
- 수집 성공·부분 성공·실패와 신규·중복 행 집계
- PAPER 판단 및 매수·매도 행동 집계
- USD/KRW와 미국 대용 지표 5종의 당일 존재 여부 검사
- 결과를 `PASS`, `WARN`, `FAIL`로 저장
- V2는 raw grid 누락·최종 provider absent·collection gap·unverified를 분리하고, 데이터 완전성과 수집 건강 상태를 따로 표시
- 시간외 RAW는 유지하며 정규장 행 수와 시간외 행 수를 구분

저장 테이블: `ml_data_quality_reports`

## 운용 조건

- FastAPI 서버가 실행 중이어야 정기 수집 작업이 동작합니다.
- 종목·국내 지수·환율·해외 지표는 PAPER 전략이 멈춰도 수집됩니다.
- 전략 판단 데이터는 PAPER 전략을 실행할 때만 생성됩니다.
- 서버를 다시 시작하면 환율·해외 지표를 즉시 한 번 수집하고 이후 예약 시각에 반복합니다.
- 실제 주문 전송 없이 PAPER 모드에서 데이터를 충분히 축적합니다.
- 서버 재시작 시 PAPER 전략은 정지 상태로 복구합니다. 데이터 수집 작업의 재개와 전략 실행 재개는 별개입니다.
- ML 정기 수집은 서버 공통 작업이며 로그인 사용자마다 별도 수집 워커를 생성하지 않습니다. PAPER 판단에는 계좌·전략 식별자를 함께 저장합니다.
- 휴대폰 앱·원격 정지는 계획만 기록했으며 현재 학습·수집 기능과 연결하지 않았습니다.
