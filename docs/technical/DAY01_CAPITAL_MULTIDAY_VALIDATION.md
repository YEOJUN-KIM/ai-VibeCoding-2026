## 2. 소스 기반 제약 의미 감사 (`auto_trader/ml/day01.py`, 읽기 전용)

신호 시점 위험 검사 순서(`risk`): 연구 무효·미청산 노출 → 일 손실 한도(`≤ −한도`) → 지연 위험 → 종목 수(`예약 포함`) → **주문 금액**(`금액+수수료 ≤ max_order_amount`) → **종목 금액**(`금액 ≤ max_symbol_amount`, 기보유 0 가정) → **총 노출**(`보유 평가+예약+금액 ≤ max_total_investment`) → 현금 부족 → 최소 현금 비율. 즉 자본(`initial_cash`)은 현금·비율 검사에만 영향을 주고, 한도 값은 자본과 별개이며 `Config`가 자동으로 스케일하지 않는다.

**사전 도출 가설(결과를 보기 전에 기록, 비교용)**: 전략의 진입 신호(5분봉 돌파·거래량·VWAP·신선도)는 자본·한도에 의존하지 않으므로 A와 B의 **신호 후보는 동일(6건)**해야 한다. 2026-11-03 감사에서 얻은 신호 시점 마지막 종가로 각 후보의 1주 비용을 계산하면:

| 후보(시각) | 종목 | 금액+수수료(원) | A: 주문한도 10만 | B: 주문한도 200만 | B: 종목한도 20만 | B: 총한도 50만 |
|---|---|---|---|---|---|---|
| 10:10:04 | `000660` | 1,420,923 | 초과(거절) | 통과 | **초과(거절)** | 초과 |
| 10:20:12 | `005930` | 222,644.25 | 초과(거절) | 통과 | **초과(거절, 금액 222,611.25 > 200,000)** | 통과 |
| 10:26:04 | `000660` | 1,418,921 | 초과 | 통과 | **초과** | 초과 |
| 10:40:02 | `005930` | 221,393.625 | 초과 | 통과 | **초과** | 통과 |
| 10:55:10 | `005930` | 222,394.125 | 초과 | 통과 | **초과** | 통과 |
| 11:15:02 | `005930` | 222,644.25 | 초과 | 통과 | **초과** | 통과 |

따라서 가설: **A는 6건 모두 `ORDER_AMOUNT_LIMIT`, B는 6건 모두 `SYMBOL_EXPOSURE_LIMIT`(주문 한도는 통과하지만 종목 한도 200,000에서 첫 거절)이며 두 경우 모두 체결 0**이다. B에서 자본·주문 한도만 늘려도 종목·총 한도가 암묵적으로 스케일되지 않으므로 결과가 달라지지 않을 수 있다(자본이 곧 체결이라는 해석 금지). 이 가설은 Codex 결과와 독립적으로 비교하며 틀리면 불일치로 보고한다. 6건 진단은 전체 재생 A/B와 **별도**로 기록되어야 하고 강제 체결이 없어야 한다.

## 3. 다일 데이터 검증 프로토콜

1. **출처 범위**: 검색은 Codex 인벤토리(기존 37개 문서화 입력·583 메타데이터)와 참조 데이터셋의 시장 파일로 한정되어야 한다. 인벤토리 외 신규 검색 흔적, 계좌·주문·백업·DB 파일 사용 여부를 확인한다(내용 읽기는 화이트리스트 11필드만).
2. **중복·충돌·우선순위(지표 계산 전에 선언되어야 함)**: 같은 `(symbol,event_at)`이 여러 스냅샷(일 단위·누적)에 있으면 **행 출처 전체(11필드) 일치 여부**로 동일 행을 제거하고, 값이 다르면 선언된 출처 우선순위 규칙으로만 처리한다. 최선·최조 선택, 결과 기반 선택, 값 혼합이 없어야 하며 **원래 `available_at`이 보존**되어야 한다. 중복·충돌 개수와 제거된 행이 보고되어야 한다. 선언 시각이 지표 계산 이전인지 로그 시각으로 확인한다.
3. **고정 universe**: 원래 22종목 그대로, top50·수익률 기반 선택 없음.
4. **날짜 적격성**: 날짜별·종목별로 오전 150분 격자(09:00~11:29) + 11:30 경계, 09:00 봉 결측(오프닝 레인지 불가), 지연(한계 2분), 가용 날짜 > 이벤트 날짜인 **백필(같은 날 신호 불가)**, 유효하지 않은 날짜(명시 근거)를 각각 집계한다. 백필된 날은 판단 시계가 `available_at`이므로 사실상 사용 불가임을 정확히 표기해야 한다(0 아닌 사유 명시).
5. **다일 연속 A/B**: 여러 날이면 하나의 연속 계좌로 실행하고, 15:10 미청산 동결이 이후 전체를 막는 한계, 다음 날 갭 미모델링, 일 단위 기준선 리셋을 보존해야 하며 **날짜별 합계를 "새 계좌의 일 집계"로 표현하는 오해가 없어야 한다**.
6. **입력 불변성**: 각 입력 파일의 실행 전·후 SHA-256·크기·mtime이 같아야 한다(이전 2026-11-03 입력 `4dfe33de…fbe030` 포함). 읽기 전용이며 저장소로 복사되지 않았는지 확인한다.

## 4. 독립 재계산 항목 (인계 후)

- 비용: 수수료 `floor(금액×0.00015)`, 세금(매도만) `floor(금액×0.002)`, 슬리피지 `|체결가−기준가|×수량`, 체결이 있으면 원장 `cash == 초기현금 + Σcash_delta` 및 부채 정합. 체결이 0이면 비용·손익은 **0이 아니라 "거래 없음"**으로 해석.
- 제약: 각 거절 후보의 금액·수수료를 입력 행에서 재계산하여 거절 사유가 맞는지(2절 표와 비교), 신호 시점에 도착한 행만 사용했는지(미래 행 없음).
- 에쿼티·MDD: 관측 시각 표본, 거래가 없으면 변동 없음. 자원 위반(`INVALID_RESOURCE_OVERRUN`)·미청산·동결 상태 확인.
- 다일: 날짜·종목 수, 결측 분 식별자, 지연 분포, 백필 건수, 중복 제거 건수를 입력에서 직접 재집계.
- 불일치가 있을 때만 시뮬레이션을 부분 재현한다. 버그 발견 시 수정하지 않고 범위·사유와 함께 별도 보고한다.
