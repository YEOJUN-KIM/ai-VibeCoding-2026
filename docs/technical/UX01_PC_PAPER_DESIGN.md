## 3. 비전문가 기준 핵심 혼란 (사실 + 가설)

사실은 코드 근거가 있고, 가설은 실제 화면 확인 전까지 가정이다.

1. **시작 버튼이 있는 곳이 첫 화면이 아니다.** (사실: 기본 탭 `dashboard`, 버튼은 `controls`.) 처음 온 사용자는 보유 종목표만 보고 "어디서 시작하나"를 찾아야 한다. 상단 상태 박스는 "전략 정지"라고 알리지만 이동 수단이 없다. (가설: 이탈·오해 유발)
2. **같은 상태가 용어가 다른 여러 곳에 있다.** (사실: 계좌 카드 "정지됨", 상태 박스 "전략 정지", `#strategy-pill`, "지금 할 일".) "실행 중" vs "정상 감시 중", "정지/중지/일시정지/긴급 정지"가 섞여 있고 정지 버튼 이름은 "일시정지"인데 상태는 "정지"다.
3. **"실행 중"이 "곧 매수"로 오해되기 쉽다.** (사실: "실행 중이어도 바로 매수하지는 않습니다" 문구는 정상 감시 분기에만 있음.) 주문이 없는 이유(조건 미충족/장 외/한도/잔액)는 03 전략 판단 탭까지 가야 자세히 보인다. (가설)
4. **정지와 긴급 중지의 차이가 한눈에 안 보인다.** (사실: 둘 다 보유 주식을 매도하지 않으며 설명은 작은 보조 문구.) 화면 안내상 정지하면 "자동 주문과 손절 감시가 멈춘다"고 되어 있으나(서버 동작은 미검증) 이 위험이 문장 끝에 묻혀 있다. (가설: 위험 과소 인지)
5. **모의 화면에 빨간 `주문 인증` 버튼이 상시 노출된다.** (사실: 헤더 danger 스타일.) 모의 긴급 중지의 위험 색상과 실계좌 인증 버튼이 같은 계열이라 구분이 어렵다. (가설)
6. 보조: 수익률 카드 두 종류(계좌 전체 / 전략 투입자금)의 차이가 라벨만으로 어렵다. (가설, 우선순위 낮음)

## 4. 목표 행동 흐름 (C: 제안)

```text
전략 설정 → 적용 확인 → [시작] → 현재 상태 → 이유 → 다음 행동 → 종목별 확인
(02 계좌·전략)           (고정 컨트롤)  (상단 요약)  (같은 카드) (같은 카드)  (03 전략 판단)
```

원칙: **시작/정지와 현재 상태는 어느 탭에서나 같은 자리에 보이고, 상태·이유·다음 행동은 한 카드에서 한 번만 말한다.**

### 상태 → 이유 → 다음 행동 표 (PAPER-01 연결)

PAPER-01(PR #5)은 `paperStatusGuide`에서 이미 `{label, reason, next}`를 만들고 "이유 · / 다음 행동 ·" 접두어를 도입했다. UX-01은 **이 데이터 구조를 재사용**한다. `label`/`reason`/`next` 문구와 `paperStatusGuide`의 분기 우선순위는 PR #5 기준 그대로 두고 UX-01에서 바꾸지 않는다(바꾸려면 PAPER-01에서 별도 합의). 아래 "통일 어휘"는 이 문구를 대체하지 않고 카드의 **보조 제목/범례**로만 덧붙인다. PR #5 병합 후 그 결과를 기준으로 배치만 바꾼다.

> **아래 표는 예시이며 전체 상태 목록이 아니다.** 긴급 정지, 첫 시세 준비 중(PR #5의 `preparingFirstFeed`), 주말, 운영 시간 대기 등은 생략되었거나 묶여 있을 수 있다. 구현 시 `paperStatusGuide`의 모든 분기를 PR #5 병합본에서 직접 열거한다.

| 사용자 단계 | `label` 예(현행 키) | 화면의 한 줄 의미 | 주 버튼 |
|---|---|---|---|
| 준비 안 됨 | 전략 정지 (전략/계좌 미선택) | 아직 시작할 수 없음 | `계좌·전략 설정하기` (02 탭 이동) |
| 준비 완료 | 전략 정지 | 준비됨, 주문 안 함 | `모의매매 시작` |
| 감시 중 | 정상 감시 중 | 조건을 보는 중. 조건이 맞아야 주문 | `일시정지`, `긴급 중지`(보조) |
| 대기 | 거래 시간/운영 시간/휴장/시세 대기, API 한도, 시세 지연 | 켜져 있으나 쉬는 중 또는 데이터 대기 | `전략 판단 보기` |
| 제한 | 신규 매수 제한 | 새 매수만 막힘, 청산 감시 유지 | `투자 한도 보기` |
| 이상 | 긴급 정지 확인 필요 (PR #5 신규, `running && emergency_stopped`) | 표시가 서로 맞지 않음. 실제 실행·중단 여부를 단정할 수 없음 | 주 버튼 없음. 상태 다시 조회만 안내. **재시작을 유도하지 않고 중단되었다고 말하지 않는다** |

PR #5 라벨이 병합 전 바뀔 수 있어 이 표의 `label`은 구현 시점에 재확인한다. PAPER-01에서 `running && emergency_stopped` 불일치의 원인은 미해결 위험으로 남아 있으며, UX-01은 이를 해결하거나 설명하지 않는다.

## 5. 정보 배치 제안 (PC 와이어프레임, 가설)

```text
┌ FOLIO · 모의매매 ─────────── 시세 연결 ● ── [실계좌 주문 인증] (중립 스타일) ┐
│ [모의 계좌 · 실제 주문 없음] 배지                                              │
├ 메뉴 ┬─────────────────────────────────────────────────────────────────────┤
│01 보유│ ┌ 실행 컨트롤 카드 (모든 탭 상단 고정) ──────────────────────────┐   │
│02 계좌│ │ ● 정상 감시 중    전략: ○○ · 계좌: 실험계좌                    │   │
│·전략  │ │ 이유 · 최신 시세로 조건 확인 중. 조건이 맞아도 잔액·한도 확인  │   │
│03 판단│ │ 다음 · 종목별 판단 확인  [전략 판단 보기]                      │   │
│04 주문│ │ 최근 시세 14:02:11 · 조건 확인 14:02:11                        │   │
│05 한도│ │ [ 일시정지 ]  [ 긴급 중지 ]  정지하면 손절 감시도 멈춥니다      │   │
│       │ └────────────────────────────────────────────────────────────────┘   │
│       │ 요약 카드(총자산·현금·수익률 2종, 라벨에 기준 한 줄)                 │
│       │ 선택된 탭 본문 …                                                     │
└───────┴─────────────────────────────────────────────────────────────────────┘
```

우선순위별 실행 항목:

- **P1 (구조)**: 기존 `#paper-operation-status`를 "실행 컨트롤 카드"로 확장해 상태·이유·다음 행동·시각·시작/정지/긴급 버튼을 한곳에 둔다. 02 탭의 3단계는 "설정 상태 확인" 중심으로 줄인다. 기존 id와 `act()` 핸들러는 유지한다.
- **P1 (용어, 보조 제목)**: 계좌 카드·pill·지금 할 일이 같은 상태를 읽게 하되, "준비 전 / 정지 / 감시 중 / 대기 / 제한 / 긴급 정지·확인 필요"는 **보조 제목/범례로만** 쓴다. PR #5의 `label`/`reason`/`next` 본문과 분기 우선순위는 바꾸지 않는다.
- **P2 (버튼 문구)**: `전략 시작`→`모의매매 시작`, `자동매매 일시정지`→`일시정지`, `긴급 중지` 유지.
- **P2 (위험 경고)**: ① 시작 전: "실제 계좌에는 주문하지 않습니다. 모의 잔액으로만 거래합니다." ② 일시정지 옆: "자동 주문과 손절 감시가 멈춥니다. 보유 주식은 유지됩니다." ③ 긴급 중지 옆: "긴급 중지 요청 후 현재 상태를 다시 확인하세요. 이 버튼은 보유 주식의 자동 매도를 뜻하지 않습니다." ①②는 현재 `index.html` 안내를 바탕으로 한 초안이다. **`index.html`의 안내 문구는 화면 텍스트일 뿐 서버 동작을 검증한 근거가 아니다.** 이번 작업은 서버 측 정지·청산 감시 동작을 확인하지 않았으므로 "즉시 멈춥니다" 같은 중단 보장이나 청산 감시 유지/중단 보장 문구는 쓰지 않으며, ②의 "손절 감시가 멈춥니다"도 구현 전 서버 동작 확인과 승인 후 확정한다. 이상 상태(긴급 정지 확인 필요)에서는 재시작이나 중단 완료를 단정하는 문구를 쓰지 않는다.
- **P2**: "실행 중이어도 바로 매수하지 않음" 안내를 모든 감시 상태에 상시 노출한다.
- **P3**: 헤더 `주문 인증` 버튼을 danger 색에서 중립 스타일로 낮추고 "실계좌"를 명시한다(주문 안전장치 자체는 변경 금지). 수익률 카드 라벨 단순화. 02 탭을 기본 진입으로 할지는 미결.

## 6. 구현 작업 분할 (모두 별도 승인 전제)

| 단계 | 내용 | 예상 허용 파일 | 선행 |
|---|---|---|---|
| UX-02 | 실행 컨트롤 카드와 상태 보조 제목 통일 | `auto_trader/static/index.html`, `app.js`, `styles.css`(또는 `theme.css`) | **PR #5 병합 또는 조정** (`app.js` 충돌) |
| UX-03 | 버튼·위험 경고 문구, 헤더 버튼 스타일 | 같은 파일 | UX-02 |
| UX-04 | 상태→표시 매핑 순수 함수 테스트 | `tests/` 신규 JS 1개 | PR #4 형식 참고, 승인 후 |
| UX-05 | 사용자 PC 화면 확인 | 코드 변경 없음 | 격리 환경과 사용자 승인 |

PR #5가 수정하는 `app.js`와 겹치므로 PR #5 병합 전에는 착수하지 않는다. 주문·위험·인증 서버 로직, 라우터, DB는 범위 밖이다.

## 7. 수용 기준과 테스트

- 어느 탭에서도 상태·이유·다음 행동·시작/정지/긴급 버튼이 같은 위치에 보인다.
- 모든 `paperStatusGuide` 분기가 `label`/`reason`/`next`를 비우지 않고 PR #5 병합본과 동일하다(통일 어휘는 보조 제목에만 사용).
- 기존 id(`start-button`, `stop-button`, `emergency-button`, `paper-strategy-select` 등)와 `act()` 동작이 불변이다. 버튼 활성/비활성 조건은 `renderControlGuide` 현행과 동일하다.
- 위험 경고 3종이 해당 버튼 가까이 표시되고 새 기능을 약속하지 않는다.
- 자동 검증(순수 함수 가능 범위)은 UX-04. 실제 동작 검증(렌더·반응·키보드·PC 해상도 레이아웃)은 격리 환경 승인 후 사용자와 함께 수행한다. 지금까지 이 중 어느 것도 수행하지 않았다.

## 8. 미결 사항

1. 기본 진입 탭을 `controls`로 바꿀지, 현행 보유 종목을 유지하고 상단 컨트롤 카드로 해결할지.
2. 실행 컨트롤 카드를 모든 탭에 고정할지, 스크롤 시 스티키로 할지.
3. PR #5 병합 시점과 문구 계약 확정 여부(UX-02 선행), `running && emergency_stopped` 불일치의 서버 측 원인과 경고 문구(②③) 확정을 위한 동작 확인.
4. `주문 인증` 버튼 스타일 변경이 LIVE 안전 정책 검토(GPT/사용자) 대상인지.
5. 실제 PC 해상도 기준과 접근성(대비, 키보드) 요구 수준.
