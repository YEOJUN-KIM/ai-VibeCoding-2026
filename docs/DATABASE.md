# PostgreSQL과 PAPER 메모리 저장

## PostgreSQL 설정

현재 PC에는 프로젝트 전용 PostgreSQL이 별도로 구성되어 있다.

- 주소: `127.0.0.1:55432`
- DB: `auto_trader`
- 사용자: `paper_local`
- 암호: Git에서 제외된 `.env`에 저장
- 데이터 폴더: `.paper-postgres/` (Git 제외)
- 접속 범위: 로컬 PC

PC를 재부팅한 경우 프로젝트 폴더에서 다음 순서로 실행한다.

```powershell
./scripts/start-paper-db.ps1
python -m auto_trader
```

앱 종료 후 DB를 중지하려면 `./scripts/stop-paper-db.ps1`을 실행한다. 다른 PC에서는 PostgreSQL에 빈 DB와 사용자를 만든 뒤 `.env`에 접속값을 입력한다. DB 연결에 실패하면 서버 시작도 중단된다.

## PostgreSQL에 영구 저장하는 데이터

- 단일 관리자 계정과 비밀번호 해시
- 로그인 실패 횟수와 잠금 상태
- 로그인 세션
- LIVE 6자리 PIN 해시와 인증 상태
- PAPER 위험 한도 프리셋과 사용자 설정

비밀번호, PIN, Client Secret의 원문은 DB에 저장하지 않는다. 토스 API 키는 Git에서 제외된 `.env`에서만 읽는다.

## 메모리에만 저장하는 PAPER 데이터

- 초기 가상 현금 1,000만 원
- 모의 보유종목과 평균 매입가
- 모의 주문과 체결 결과
- 모의 수수료·세금과 손익
- 이동평균 가격 기록과 매매 신호
- 당일 주문 횟수와 PAPER 손익 기준값

PAPER 데이터는 서버 프로세스가 실행되는 동안만 유지된다. 로그아웃이나 재로그인만으로는 초기화되지 않으며, 서버를 종료했다가 다시 실행하면 1,000만 원의 새 계좌로 시작한다. 화면의 연습 기록 초기화 버튼을 사용하면 서버를 끄지 않고도 즉시 초기화할 수 있다.

과거 버전에서 생성한 `orders`, `executions`, `positions`, `signals` 등의 테이블은 호환을 위해 남아 있을 수 있지만 현재 PAPER 기능은 이 테이블을 읽거나 쓰지 않는다. 실제 거래 기록 기능을 만들 때는 PAPER 기록과 완전히 분리된 테이블을 새로 설계한다.

## 감시 종목

서버 시작 시 토스증권 API에서 국내 일일 거래대금 상위 10개를 조회한다. 투자유의 종목은 제외한다. 조회한 현재 가격을 가상 시세의 시작 가격으로 사용하고, 이후 PAPER 전략은 실제 가격이 아닌 가상 변동 가격으로 연습한다.

토스 API를 사용할 수 없으면 코드에 포함된 국내 대표 종목 10개와 예시 가격을 대신 사용한다.

## 모의 비용과 손익

- `PAPER_FEE_RATE=0.00015`: 매수·매도 수수료 예시 0.015%
- `PAPER_SELL_TAX_RATE=0.002`: 매도 세금 예시 0.2%
- 실제 증권사 수수료나 현행 세율을 의미하지 않는다.
- 각 체결 대금에 비율을 곱하고 원 미만을 절사한다.
- 매수 평균단가는 매수 수수료를 포함한다.
- 총손익 = 현금 + 보유주식 평가금액 - 초기 자금
- 평가손익 = 보유주식 평가금액 - 매수 수수료 포함 취득원가
- 실현손익 = 총손익 - 평가손익

## 동시성과 중복 요청

메모리 모의계좌는 프로세스 내부 잠금을 사용해 동시에 들어온 주문이 같은 현금을 중복 사용하지 못하게 한다. `request_id`가 같은 재시도는 기존 결과를 반환하고, 같은 ID로 다른 주문을 보내면 충돌 오류를 반환한다.

현재는 단일 앱 프로세스와 단일 모의계좌만 지원한다. 여러 서버 프로세스나 uvicorn 다중 워커를 사용하면 각 프로세스에 별도 PAPER 계좌가 생기므로 사용하면 안 된다.
