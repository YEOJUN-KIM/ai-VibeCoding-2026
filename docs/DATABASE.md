# PostgreSQL과 PAPER 메모리 저장

## PostgreSQL 설정

현재 개발 환경은 Windows에 설치된 PostgreSQL 18 서비스를 사용한다.

- 주소: `127.0.0.1:5432`
- DB: `auto_trader`
- 사용자: `paper_local`
- 암호: Git에서 제외된 `.env`에만 저장
- 접속 범위: 로컬 PC

Windows를 재부팅하면 PostgreSQL 서비스가 함께 시작되므로 일반적으로 별도 DB 시작 스크립트가 필요하지 않다. 프로젝트에 남아 있는 `scripts/start-paper-db.ps1`과 `stop-paper-db.ps1`은 과거의 프로젝트 내부 DB(`.paper-postgres`, 포트 `55432`)용이며 현재 기본 설치 방식에서는 사용하지 않는다.

다른 PC에서 DB와 사용자를 만드는 전체 순서는 [Windows 설치 가이드](INSTALL_WINDOWS.md)를 따른다. DB 연결에 실패하면 데이터 유실이나 인증 우회를 막기 위해 서버 시작도 중단된다.

## PostgreSQL에 영구 저장하는 데이터

- 단일 관리자 계정과 비밀번호 해시
- 로그인 실패 횟수와 잠금 상태
- 로그인 세션
- LIVE 숫자 6자리 PIN 해시와 인증 상태
- PAPER 위험 한도 프리셋과 사용자 설정
- 사용자별 국내 관심종목(최대 20개)

비밀번호와 PIN 원문은 DB에 저장하지 않는다. 토스 Client Secret과 DB 암호는 `.env`에서만 읽으며 Git에 커밋하지 않는다.

### 관심종목 테이블

`favorite_stocks`에는 사용자 ID, 6자리 국내 종목코드, 종목명, 시장과 추가 시각을 저장한다. 사용자와 종목코드 조합은 중복될 수 없으며 관리자 계정이 삭제되면 연결된 관심종목도 함께 삭제된다.

현재가, 오늘 등락률과 인기 순위는 저장하지 않고 화면 조회 시 토스 API 데이터와 합친다. 따라서 과거 가격 기록을 의미하지 않는다.

## 메모리에만 저장하는 PAPER 데이터

- 초기 가상 현금 1,000만 원
- 모의 보유종목과 평균 매입가
- 모의 주문과 체결 결과
- 모의 수수료·세금과 손익
- 이동평균 가격 기록과 매매 신호
- 당일 주문 횟수와 PAPER 손익 기준값

PAPER 데이터는 서버 프로세스가 실행되는 동안만 유지된다. 로그아웃이나 재로그인만으로는 초기화되지 않으며, 서버를 다시 실행하면 초기 가상계좌로 돌아간다. 화면의 `오늘 연습 기록 초기화`를 사용하면 서버를 끄지 않고도 즉시 초기화할 수 있다.

`orders`, `executions`, `positions`, `signals` 등 거래용 테이블은 향후 영구 기록과의 호환을 위해 스키마에 있지만 현재 PAPER 엔진은 메모리를 사용한다. 실제 주문을 구현할 때는 PAPER 기록과 혼동되지 않도록 별도 상태·대조 규칙을 먼저 설계한다.

## 토스 LIVE 데이터

실제 계좌의 보유종목, 평가금액, 원화·외화 매수 가능 금액, 현재가와 등락률은 토스 API에서 읽는다. 계좌값은 이 DB에 복사해 영구 저장하지 않는다.

API 호출 제한을 줄이기 위해 일부 조회는 서버 메모리에서 짧게 캐시한다. 서버를 여러 개 실행하거나 브라우저를 매우 빠르게 반복 새로고침하면 토스 API의 `429` 제한이 발생할 수 있다.

## 감시 종목과 검색 순위

서버 시작 시 국내 일일 거래대금 상위 종목을 조회해 PAPER 감시 종목의 시작 가격으로 사용한다. API를 사용할 수 없으면 코드에 포함된 대표 종목과 예시 가격을 사용한다. 이후 PAPER 가격 변화는 실제 시세가 아니라 가상 값이다.

LIVE 종목 검색 결과는 당일 거래대금 순위를 우선해 인기순으로 정렬한다. 검색어와 일치하는 모든 시장 종목을 무제한 표시하지 않고 한 페이지에 8개씩 보여 준다. 종목의 `산업` 정보는 현재 토스 공식 Open API 응답에 없으므로 저장하거나 표시하지 않는다.

## 모의 비용과 손익

- `PAPER_FEE_RATE=0.00015`: 매수·매도 수수료 예시 0.015%
- `PAPER_SELL_TAX_RATE=0.002`: 매도 세금 예시 0.2%
- 실제 증권사 수수료나 현행 세율을 의미하지 않는다.
- 각 체결 대금에 비율을 곱하고 원 미만을 절사한다.
- 매수 평균단가는 매수 수수료를 포함한다.
- 총손익 = 현금 + 보유주식 평가금액 - 초기 자금
- 평가손익 = 보유주식 평가금액 - 매수 수수료 포함 취득원가
- 실현손익 = 총손익 - 평가손익

## 동시성과 중복 요청

메모리 모의계좌는 프로세스 내부 잠금을 사용해 동시에 들어온 주문이 같은 현금을 중복 사용하지 못하게 한다. `request_id`가 같은 재시도는 기존 결과를 반환하고, 같은 ID로 다른 주문을 보내면 충돌 오류를 반환한다.

현재는 단일 앱 프로세스와 단일 모의계좌만 지원한다. Uvicorn 다중 워커를 사용하면 프로세스마다 별도 PAPER 계좌와 API 캐시가 생기므로 사용하지 않는다.

## 검증

```powershell
python -m unittest discover -s tests -v
```

테스트는 임시 PostgreSQL 스키마를 사용해 관리자·PIN·위험 설정·관심종목을 검증한다. PAPER 초기화, 중복 요청, 동시 주문, 비용, 위험 한도와 토스 응답 처리도 함께 확인하고 테스트가 끝나면 임시 스키마를 제거한다.
