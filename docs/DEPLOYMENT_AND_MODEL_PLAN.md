# 배포·운영과 머신러닝 모델 개선 계획

기준일: 2026-10-04

이 문서는 배포 방식, 기기 이동, 모델 제공과 사용자 데이터 참여에 관한 논의를 보관합니다. 계획을 기록했다는 이유로 구현을 시작하거나 완료된 기능으로 취급하지 않습니다. 현재 동작은 [CURRENT_STATE.md](CURRENT_STATE.md), 가까운 작업은 [ROADMAP.md](ROADMAP.md), 머신러닝 진행 상태는 [구현 현황](machine-learning/CURRENT_PROGRESS.md)을 기준으로 합니다.

## 상태 구분

| 표시 | 의미 |
|---|---|
| 현재 구현 | 코드에 있는 기능. 실제 운영 검증 여부는 현재 상태 문서에서 별도로 확인 |
| 합의한 방향 | 사용자와 정한 제품 방향. 구현 완료를 뜻하지 않음 |
| 검토 중 | 가능한 방안이며 도입 여부·세부 정책은 미정 |

## 운영 방향

- **합의한 방향:** 개인용 Windows 로컬 프로그램을 기반으로 한다. 공개 회원가입을 받는 다중 사용자 서비스와 유료 서버에서의 매매 실행은 당장 추진하지 않는다.
- **합의한 방향:** 향후 휴대폰에서는 집 PC가 켜져 있을 때 실행 상태를 확인하고 필요하면 정지하는 기능을 검토한다. 지금은 앱 제작·외부 접속 개방을 하지 않는다.
- **합의한 방향:** 토스 로그인 도입은 보류한다. 사이트 로그인과 증권 연결 권한을 구분한다.
- **현재 구현:** 로컬 웹앱, 사용자별 연결·모의계좌 분리, API 키의 로컬 보관과 FOLIO.cmd 간편 실행이 있다. 설치 프로그램·휴대폰 원격 제어·자동 설정 동기화는 없다.

휴대폰 정지의 대상, 실행 PC의 처리 확인, 연결 끊김 표시는 [BACKLOG.md](BACKLOG.md#휴대폰-연결-앱-구현-보류)에 정리한다.

## 컴퓨터를 바꾸거나 추가할 때

프로그램 파일, 개인 설정·거래 기록, API 키, 학습된 모델은 별개로 관리한다. 새로 설치하는 것만으로 개인 데이터가 다른 기기에 따라오지는 않는다.

| 사용 방식 | 데이터 처리 | 상태 |
|---|---|---|
| A PC를 실행 주체로 두고 B PC·휴대폰에서 접속 | A의 설정·DB를 조회하고 제어. B에서 별도의 매매를 실행하지 않음 | 검토 중, 원격 연결 미구현 |
| B PC에 독립 설치 | 별도 설정·DB로 시작. A의 기록은 A에 남음 | 현재 자동 동기화 없음 |
| A에서 B로 완전히 이전 | 백업을 복원하고 API 키를 재등록. 매매 실행 PC를 하나로 정함 | 이전 절차·전체 복원 검증 필요 |
| 여러 기기에 설정 동기화 | 동기화할 설정과 기기별 설정, 충돌 처리 기준을 정해야 함 | 검토 중 |

현재 새 API 키 파일은 Windows 암호화에 묶여 있어 다른 Windows 사용자·컴퓨터로 파일만 옮겨 사용할 수 있다고 가정하지 않는다. 기존 관리자 키는 `.env`, 새 키는 `.local-secrets/`에 보관한다. 저장·백업 범위는 [DATABASE.md](DATABASE.md)를 따른다.

## 프로그램 배포와 초기 설정

**검토 중:** 개발 환경을 직접 설치하는 방식 이후, 설치 파일을 제공하는 개인용 프로그램으로 배포할 수 있다. GitHub Releases 등은 후보이며 배포 경로를 확정하지 않았다.

설치형 배포를 결정하면 다음을 정한다.

- Python·DB 등 실행에 필요한 구성 요소를 설치·실행하는 방법
- API 키가 없는 첫 실행에서도 로그인 후 연결을 등록하는 순서
- 설치 파일과 분리한 사용자 데이터 폴더, 업데이트 시 설정·DB 보존
- 백업·복원과 새 PC 이전, API 키 재등록 안내
- 버전별 변경 내용과 설치·업데이트 실패 시 복구 방법
- 제작자의 API 키·개인 계좌 기록·개발용 설정을 배포에서 제외

현재는 개발용 설치 절차다. DB와 관리자 계정을 준비하면 증권 연결 없이 로그인할 수 있으며, 키가 없거나 로컬 키 파일을 잃었으면 계정 설정에서 등록·복구한다. 설치 프로그램의 DB·관리자 초기 설정과 실제 키 변경 운영 검증은 별도로 준비해야 한다.

## 학습과 모델 사용의 구분

**검토 중:** 개발자가 학습·검증한 모델을 프로그램에 포함하거나 별도 다운로드로 제공한다. 사용자마다 처음부터 학습할 필요는 없다. 사용자는 현재 시세를 모델에 넣어 판단 결과를 얻는다.

현재는 원본 데이터·전략 판단 수집과 이동평균 기반 백테스트가 있다. 환경 확인용 예제 모델은 실제 매매 모델이 아니며, 검증된 머신러닝 매매 모델 배포·실시간 적용은 아직 없다.

모델 제공을 결정하면 모델 버전, 필요한 입력 데이터·전처리, 지원 프로그램 버전을 함께 관리한다. 학습 기간과 별개의 기간으로 평가하고 거래비용·누락 데이터·과최적화를 검토한다. 새 모델이라는 이유만으로 성능 향상이나 수익을 보장하지 않는다.

모델 업데이트는 프로그램 업데이트와 분리할 수 있다. 적용 승인, 실행 중 교체 방지, 이전 모델 복구 방식은 검토 중이며 자동 업데이트는 아직 합의하지 않았다.

## 사용자 데이터 참여와 모델 개선 구조

**검토 중:** 아래는 가능한 역할 분담이다. 수집 서버 도입과 사용자 데이터 전송은 결정·구현하지 않았다.

| 역할 | 담당 작업 |
|---|---|
| 사용자 PC | 시세 수집, 전략·한도에 따른 자동매매, 배포된 모델 사용, 로컬 기록 |
| 수집 서버 | 참여자가 허용한 항목 수신, 형식·누락·중복 확인, 저장 |
| 개발자 PC | 필요한 데이터를 내려받아 정리·학습·검증 |
| 배포 경로 | 검증한 모델 파일과 버전 정보를 사용자에게 제공 |

흐름: 사용자 PC의 기록 → 선택적 데이터 제공 → 수집·정리 → 개발자 학습·평가 → 검증을 통과한 모델 배포 → 사용자 적용.

수집 서버는 매매나 학습까지 담당할 필요가 없다. 개발자 PC에서 주기적으로 학습하면 학습용 GPU 서버를 상시 운영할 필요도 없다. 학습 자원이 부족해질 때 별도 자원 이용을 검토한다.

### 초기에는 파일로 시작하는 방안

사용자가 학습용 기록을 파일로 내보내고 개발자가 받아 정리·학습한 뒤 모델을 배포할 수 있다. 이 경우 데이터 제공을 위해 상시 수집 서버를 빌릴 필요는 없다. 내보내기와 안전한 전달 방법은 아직 구현하지 않았다.

참여자가 늘어 수동 전달이 번거로워지면 수집 서버와 자동 전송을 검토한다. 연결 실패가 로컬 매매를 막지 않도록 하고, 전송 재시도·보관 용량·삭제 정책을 정한다.

### 수집 대상과 품질

- 참여하지 않아도 로컬 프로그램을 사용할 수 있는 방향을 권장한다. 참여·철회·삭제 범위는 착수 전에 정한다.
- 후보 항목은 종목·시각별 시세, 모델·전략 버전과 판단, 이후 가격 변화 등이다. 실제·모의 결과를 구분하며 세부 항목은 미정이다.
- API 키·비밀번호·PIN·계좌 식별정보는 제공 데이터에서 제외한다. 거래 기록도 원본 전체 전송을 기본으로 삼지 않고 필요한 항목만 검토한다.
- 같은 종목·시각의 시세를 여러 명이 보내도 새로운 시장 정보가 그만큼 늘지는 않는다. 중복 제거와 출처·시간대·수정 이력·누락 검사가 필요하다.
- 전략 조건·거래비용·모델 버전이 다른 결과를 같은 조건의 성과로 합치지 않는다. 종목과 날짜 범위의 다양성, 독립된 평가 구간을 확보한다.
- 외부 제공 데이터의 수집·공유·학습 이용 조건은 수집 범위를 정할 때 확인한다.

## 도입 순서 후보

아래는 권장 순서이며 확정 일정이나 구현 지시가 아니다.

1. 개인 PC에서 현재 기능과 초기 설정·복구를 안정화한다.
2. 설치 파일, 사용자 데이터 보존, 백업·이전 절차를 준비한다.
3. 집 PC가 실행 중일 때 휴대폰 상태 확인·정지를 검토한다.
4. 충분한 데이터로 모델을 검증하고 모델 파일 제공을 검토한다.
5. 선택적인 파일 내보내기로 데이터 참여의 효용을 확인한다.
6. 필요성이 확인되면 수집 서버와 모델 업데이트 전달을 자동화한다.
